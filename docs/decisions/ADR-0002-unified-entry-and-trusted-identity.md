# ADR-0002：统一入口与可信身份边界

- 状态：Accepted；2026-10-06 在独立集成分支实施最低边界，真实提供方配置与人工验收尚待完成，见 [实施说明](../architecture/unified-integration.md)。下述背景为 2026-10-05 方案基线。
- 日期：2026-10-05
- 决策依据：用户确认保留 Part A 7860 页面、OIDC 登录、身份权限库及可过滤的 Qdrant 后端，并明确系统内撤权为本轮重点。
- 关联需求：REQ-015、REQ-016、REQ-017；复用 REQ-002 至 REQ-009 的安全要求。

## 背景

GitHub main 的 Part A 数据与检索演示和旧 Streamlit 安全问答演示共处一个仓库，但使用不同的数据、身份、权限与服务。旧版权限变化不影响 Part A，Part A 数据也未进入旧回答和审计服务。

## 已确认决策

1. 保留 Part A 的 7860 页面作为集成版入口，迁移旧 Streamlit 的服务能力，而不是继续维护两套独立业务状态。
2. 使用 OIDC 验证真实身份；具体登录提供方尚未选定。
3. 增加持久化身份权限库，保存真实账号映射、组织与组、角色、项目、本地限制和权限版本。
4. 所有业务接口使用可信登录身份及当前权限，不接受前端任意指定的演示身份。
5. 结构化事实库、身份权限库与可重建的检索索引具有不同职责。向量索引不能替代身份权限库或标准化原文存储。
6. 集成版向量检索采用可过滤的 Qdrant 后端，复用 Part A 的来源解析、原始与标准化存储；原 RaBitQ 索引不能继续充当集成版唯一向量检索路径。
7. 本轮先保障系统内权限撤销；原平台撤权自动发现与同步暂缓，但预留来源权限检查 / 同步接口。未启用时显示 not_enabled 或 unknown，不宣称实时同步，也不取消既有来源 ACL 保真要求。
8. 2026-10-05 先记录方案、不修改业务代码；2026-10-06 用户授权在独立分支实施集成，未经人工验收确认不合并 main。

## 待确认事项

- 生产级 Qdrant 部署、增量发布与恢复；首版已经实现回环部署、payload 过滤、整快照迁移／发布和撤权验证。
- OIDC 提供方、应用注册、回调地址与部署配置。
- 离线数据推断 ACL 与真实身份权限库的映射、可信依据及改造方式；用户明确留待后续讨论。
- 后续启用来源平台权限同步时的鉴权、接口实现、失败行为与时效窗口；本轮只定义预留边界。
- 生产级审计存储与外部不可变锚定。

## 结果

问答、检索、原文读取、权限管理与合规审计共享同一应用身份权限边界。索引重建不得清除身份权限与审计数据。已确认方向不等于已实现能力；验收和代码影响范围在实施阶段继续补充。

完整图、当前代码证据与待确认边界见 [集成架构方案](../architecture/integration-plan.md)。

索引和新鲜度的完整机制见 [设计草案](../architecture/index-and-freshness.md)。首版已实现相对已知快照的一致性门闩，完整版本历史、回滚和实时来源新鲜度仍未实现，不能仅因选定 Qdrant 就视为已具备。
