# ADR-0007：多模式确定性权限接入契约

- 日期：2026-10-15。
- 状态：Proposed（用户已确认目标和本轮保留现有 ACL 的范围；具体统一契约为本次方案，不代表获准全部实施）。
- 关联：REQ-003/permission_provider_contract_v2、REQ-002、005、016、017。
- 承接：ADR-0005 的受限原生来源适配和 ADR-0006 的功能分包，不替换当前运行路径。

## 背景

公共测试语料缺乏完整项目、密级和部门标签，不能代表企业来源缺乏原生权限。当前Security Lens的来源/文档撤权不覆盖企业权限接入的全部语义。用户要求设计可接入Slack、企业属性和服务器rwx等既有权限依据的接口；不要求在现有数据上真实启用，不要求使用模型解析权限。

## 提案

1. 定义统一PermissionProvider及身份、资源权限、检索前可见范围和决定的版本化契约；输入必须来自可信目录、源系统或批准的策略配置，LLM不作为授权依据或必经环节。
2. 定义snapshot_acl、native_acl、attribute_policy、posix_acl、external_pdp五种模式。每资源一种明确主依据，所有mandatory限制同时满足；保留原生优先级/继承/mask，不任意取并集或在失败时回退放行。
3. 项目、部门和密级支持显式企业属性策略；POSIX模式处理UID/GID、目录搜索和access ACL并限定验证范围；外部PDP必须能产生安全的检索前范围，不能只做候选召回后的单篇检查。
4. 未知、不完整、过期和不支持语义均阻断受影响范围。权限、策略及身份变化共同使旧决定失效；复用现有安全发布、原文/模型/交付复核与审计。
5. 当前数据集保留原有ACL和本地撤权，服务器不因该设计迁移或重建。新增契约和适配模式保持planned；实施需独立代码、测试和验收，不能以方案文档宣称实现。
6. 报告可以介绍设计扩展，并明确区分已实现快照/受限平台适配、新设计和真实环境未验证。本轮提供可直接引用的中英文草稿，不直接修改提交报告。

## 代价与待落实事项

- 稳定身份目录、权限时效和查询前范围编译是实际接入成本。
- POSIX DAC不能独自代表包含强制访问控制、网络文件系统规则的所有文件服务器语义。
- 当前单值项目及空属性语义需在未来迁移时明确处理，不直接套用多项目契约。
- 统一快照接口、可信发布通道、策略编译器、来源实测与性能验证尚未实现；默认关闭新增模式。

完整方案、契约示例、来源依据、后续验收矩阵和报告草稿见[权限接口v2](../architecture/permission-interfaces-v2.md)。
