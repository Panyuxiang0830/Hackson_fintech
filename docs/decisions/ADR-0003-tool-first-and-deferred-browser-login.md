# ADR-0003：延期浏览器登录，保留当前前端验收

- 状态：Accepted（经用户澄清修正）；仅延期真实登录，Tool 为 deferred 的未来设想，用户已确认隔离演示入口。
- 日期：2026-10-06
- 决策依据：用户先提出未来可能作为上游大模型 / Agent 的 Tool，要求先切掉登录步骤，随后明确“Tool 是后面的设想，现在还不用管”，当前继续在 Part A 前端验收集成。先前把该表述解释成“工具优先”过度扩展了范围，本 ADR 据此纠正。
- 关联需求：REQ-016、REQ-017、REQ-020；继续复用 REQ-002 至 REQ-009。
- 替代范围：仅替代 ADR-0002 中“本轮必须完成本系统浏览器 OIDC 登录”的部分；Part A 前端、存储、身份权限库、权限过滤、系统内撤权及审计决策继续有效。

## 决策

1. 停止继续配置 Auth0，不复制或保存 Client Secret，不创建真实用户、不引导管理员提权。已创建的 Auth0 应用保留，不自动删除或轮换凭据。
2. 浏览器登录默认停用，前端不提供登录入口，已有 OIDC 配置与旧会话不能隐式恢复业务访问。保留已有代码和隔离协议回归测试，不把已投入的登录工作当作本轮交付前置条件。
3. 保留 Part A 风格页面作为当前集成和人工验收入口，继续验证搜索、自然语言回答、权限管理和审计；不等待 Tool 实现。
4. 去掉登录页面不等于去掉身份权限库或权限检查。生产身份仍须验证；模型生成的 user_id、角色或 principal 不构成身份证明。隔离演示入口在本轮实现，不作为生产身份验证。
5. REQ-020 记为 deferred；具体 MCP、HTTP 工具或本地调用协议留待后续，不在本轮擅自引入，也不要求先选工具协议。
6. 用户确认在回环／SSH 预览中显式配置独立演示账号、权限和审计状态：一个“ContextLedger 管理员”和六个员工，用实际统一服务验收并同步到 gpushare。演示模式默认关闭，与 OIDC 互斥，固定名单、CSRF 和回环 Host／Origin 检查，拒绝已有非演示权限库；初始化／重启不自动重置撤权。不把演示选择身份当作生产鉴权，也不通过 Flask TESTING 暴露测试会话。非演示生产业务 API 仍需验证身份。
7. 所有改动保留在 `codex/REQ-017-unified-integration`，未经人工验收不合并 main。

## 当前与后续验收

本轮先解决前端演示入口缺口，再在 Part A 风格页面验证两个员工对同一问题只得到各自授权证据、管理员撤权、真实模型 provider 与回答引用，以及请求 ID 对应的审计链。管理员管理角色不自动授予业务资料读取权限，审计详情仍按当前权限脱敏。

后续实现 REQ-020 时另行验证上游最终用户身份；共同使用一个服务凭据不能自动证明最终用户身份。浏览器登录停用的本地修改尚未部署到服务器，运行中的 17860 仍可能显示旧 OIDC 提示；范围记录不等于完成部署或人工验收。

范围、当前实现与待确认事项见 [工具入口范围](../product/tool-entry-scope.md)。
