# ADR-0005：只读来源适配与宿主模型优先 MCP

- 日期：2026-10-14。
- 状态：Accepted（用户确认方案并授权在新分支实现；代码、联调与验收分开）。
- 需求：REQ-003、004、014、016、017、020，继续遵守权限、撤权和审计边界。

## 决策

1. 四来源提供明确配置、限定范围、只读数据及可验证权限读取。Jira/Confluence 第一版仅 Cloud；Slack 按频道线程；Drive 按配置文件夹的直接子文件。
2. 原生身份到既有 canonical principal 显式映射，不按姓名猜身份；原生权限检查自动产生文档 ACL，未知/不支持内容隔离，不能给采集账号可读的资料统一放行。
3. 复用文档更新队列安全发布，不直接修改 Qdrant。权限就绪状态保存在身份库，刷新/失败/过期时保守阻断该 corpus；不冒充实时原平台撤权。配置默认停用，定期拉取必须由运维显式启动。
4. 默认由宿主模型基于 search/fetch 的授权证据回答，不调用内部规划/生成模型。可选 ask/audit 内部生成复用现有 GLM/OpenAI-compatible 配置，凭据只在服务端，两个路线共存。
5. 首版提供 MCP stdio，连接到单独的私有 HTTP 工具 API。该 HTTP API 不是 MCP Streamable HTTP；标准远程 MCP、企业 OAuth、客户端发行插件后续单独交付。三端配置示例不等于三端已验证。
6. 每个工具凭据绑定单一稳定用户，保存哈希、能力范围和有效期，可撤销；每次操作/交付检查账号、权限、索引、凭据。模型不能选身份、URL、API Key、角色或 ACL。
7. 不恢复 Auth0/浏览器登录、第二模型引用复核，不把管理、数据同步或写入工具开放给普通 Agent。现有前端与后端继续保留。

## 验证边界

用户本轮要求不运行测试或真实平台联调。本分支提供待运行的离线回归用例；不使用旧测试数字、不标 validated、不启动服务或产生真实平台/模型请求。

替代 ADR-0003/0004 中“本轮不实现对外工具”的阶段性范围；原身份与隔离边界不变。实现和配置详见 [接口说明](../architecture/source-and-agent-interfaces.md)。
