# ADR-0004：默认自动调用内部 Decision Radar 工具

- 日期：2026-10-12
- 状态：Accepted；本地 v1 已实现，生产与完整语义验收另记。
- 依据：用户确认其余理解一致，并明确取消手动切换、采用系统提示词中的自动工具调用、有依据给结论/不足说明原因。
- 关联需求：REQ-011、REQ-004、REQ-017、REQ-018/019，权限/模型边界沿用既有需求。
- 分支：feat/decision-radar-v1。

## 决策

1. 保留现有 /api/ask 和统一服务问答入口；LLM 根据问题与首轮授权证据直接回答或请求内部 decision_radar 工具。前端无普通/自动/Radar 切换、工具按钮或专用入口。
2. 文本照常存储，不要求预先由模型打业务/项目主体标签；可选轻量明确 ID 索引，查询时按问题定位主体并组织事件/关系。实际来源修订与底层版本管理继续保留。
3. 内部工具由服务端执行，复用当前身份、Scope、权限/版本/交付检查与审计。模型不能指定身份/权限或执行任意 SQL/网络请求。最多一次工具调用，内部最多两轮补查，设资料和模型预算。
4. 工具返回授权证据、来源状态与关联线索，交给同次问答模型完成最终结论。来源和引用可确定性检查；不恢复已取消的第二模型复核/反馈重答，不宣称逐句语义保证。
5. 可靠性按待证明事实与原始记录类型判断：Jira 工单状态、PR 合并/revert、生产回滚与运行恢复分别表达，普通聊天和可验证 bot 回执分开。支持充分给结论，部分支持说明边界，不足/冲突说明原因。
6. 新资料先通过四案例分阶段小快照验证安全发布与可见时效；评测真值、未来评论和最终快照状态不得提前进入业务输入。真实平台 ACL/增量同步和未见测试集效果分开报告。
7. 这次是应用内部 LLM 工具能力，不实现 REQ-020 的外部 Agent/MCP/插件协议，既有身份和登录边界不变。

## 被替代的草案

本决定替代此前 Proposed 方案中的前端手动策略选择、独立 /api/radar 用户入口和预建全库业务实体/事件/关系表。已有原文、来源修订、统一权限与查询审计仍是证据基础。

## 取舍与实施

自动调用降低用户操作负担，增加错调用/漏调用、模型费用和时延风险；需正反例实测。工具有界补查和可靠性规范不能保证找到所有关联或解决所有语义分歧；回答需说明本次资料范围。发布和历史内容读取需要扩展当前一致性检查，不直接热写现有库。

完整工具契约、接口兼容、数据、更新、分阶段开发及验收见 [最终方案](../architecture/decision-radar-v1.md)。

## 2026-10-12 补充

按用户要求将默认资料容量从40提高到120，独立控制模型正文／时间／关联轮数预算并展示具体截断原因。查询时增加名称／多语言检索短语规划，先查授权候选再从实际材料提取编号；不硬编码案例别名、不新增入库实体标签。原 QueryPlanner 协议保留，仅更新 Prompt 和问答侧的单候选发现处理；明确名称纠错仍停止，多候选不静默合并。
