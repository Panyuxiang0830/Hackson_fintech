# Radar综合阶段推理模型比较与路由

2026-10-13，REQ-011 / `radar_reasoning_synthesis`，team_decision。主功能与既有引用/权限门闩沿用ADR-0004。本改动不恢复第二模型语义复核。

## 当前审计脱敏与输入边界

审计日志中的证据逐条核对查询人的当前业务读取权、当前文档版本/哈希和索引可用性。只要任一证据不满足，整条事件的历史问题、答案、证据明细、文档ID及授权明细屏蔽；保留序号、请求ID、时间、事件类型、人员/角色、权限与策略版本、决策。业务证据数量在不能读取时为unknown；任意附加诊断字段不进入页面投影。这是权限驱动的字段屏蔽，没有执行通用姓名/手机号识别。没有证据的事件当前也走保守屏蔽分支，因此不能把redacted一概解释为历史请求曾经越权。

页面事件明细与模型输入不同：模型只接收序号/E引用、时间、事件类型、用户ID/姓名/角色、权限与策略版本、决策、可见证据数量、redacted、最多1000字符原问题、1500字符答案、前5个可见资料ID及截断标志。当前模型投影没有请求ID、完整授权规则明细或所有证据正文，所以“为什么允许”只能解释输入确实提供的事实。

日志选择最多100条，模型一次最多20条及40,000字符，按日志顺序选取，超过明确提示截断。20条适合少量请求核对，不能代表整周完整统计。后续可以加分页、按问题挑关键/异常事件、完整匹配集合的数据库计数/分组，再让模型解释统计与样例；本次不增加审计容量。

## 比较方法

固定任务三的自然语言问题、37条授权资料、citation ID与工具报告。逐条资料仍使用生产综合阶段24000字符分配规则。原提示的Flash请求输入8142tokens，与前轮最终模型调用一致。只比较最后生成阶段，避免不同检索结果混入。所有配置统一最多6000输出tokens；这比旧生产1600上限更高，不能把全部差异归因于换模型。

每配置两次独立调用，共12次，无模型裁判。只保留最终回答和用量，不保存reasoning_content。语义人工核对关联/因果、来源报告与实际恢复、时间缺口；当前严格格式和引用校验另计，失败不能算交付成功。原始结果保存在ignored的 `runtime/radar-reasoning-compare-20261013/results.json`，不是独立测试集。

## 最终选择与配置

普通回答/工具选择保持 `LLM_MODEL` 和 `LLM_REASONING_EFFORT`（默认Flash low）。只有服务端成功执行内部Radar后，最终综合调用才使用：

```dotenv
RADAR_LLM_REASONING_EFFORT=high
RADAR_LLM_MAX_TOKENS=6000
RADAR_LLM_TIMEOUT_SECONDS=60
```

用户最终选择Flash high，不启用旗舰模型。综合阶段与普通路径使用同一个LLM_MODEL（默认glm-5.3-flash）；旧RADAR_LLM_MODEL不生效，也不进入预览配置同步。旗舰候选测试仅作为比较记录，本版不保留其专用参数适配。tokens限制1600–8000，timeout限制10–120秒，不为模型失败无限延长预算。

模型选择不能由用户正文或工具参数指定。不改变身份/检索范围，不新增语义复核调用；格式重试只在已完成的综合阶段重试，不再运行工具。失败保留证据、安全降级，不自动切换到Flash编造答案。诊断记录调用阶段、requested/actual model、预算与用量，最终provider对应实际返回模型。
