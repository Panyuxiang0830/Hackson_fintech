# 合规审计查询流程与时间条件

关联 REQ-008。当前实现以受限规则识别查询条件，后端执行查询与统计，模型解释有界事件和明确的统计结果，不执行任意SQL或决定权限。2026-10-16用户确认管理员完整审计；管理员历史日志读取与业务文档读取资格分离，compliance保留原脱敏规则。

1. /api/audit/ask检查当前admin/compliance角色和会话，普通员工拒绝；审计问答本身继续入链。
2. 管理员使用四类工作台：读取已验证哈希链快照，临时SQLite索引执行完整过滤、精确计数、分组和稳定分页。界面与AI复用同一选择范围。完整字段及布局见[四区工作台](../product/audit-console-v2-plan.md)。
3. 管理员可查看已记录历史问题、回答、资料ID/版本和权限变更，不再取决于当前业务原文是否可读或版本是否仍相同；未记录的历史内容不补造。模型前后/HTTP交付仍复核管理员角色、epoch和日志完整性。
4. 新权限日志保存操作者、受影响员工、操作ID、before/after和目标epoch。新原文失败保存请求ID；资料更新补任务、旧/新版本、对象和结果。旧哈希链不改写。
5. AI最多读取20份分类型代表事件和40k字符，精确统计另由后端完整筛选计算。[E序号]跳转事件，[Q1]指向显示的查询范围及完整统计；事件明细不足或模型失败时说明范围并保留实际结果。
6. SGT用于新管理员界面日期与自然语言今天/昨天，API明确时间必须带时区并转换UTC；其他受支持相对时段沿用确定性规则，未支持条件仍报错。显式条件查询可覆盖自然语言范围。
7. compliance继续使用下述早期流程：按当前证据读取权、版本/哈希释放历史正文和证据，最多100条有界选择与20条模型明细；禁止隐式扩大此角色的数据范围。

## 2026-10-13 时间解析修复

- `过去一周`、`最近一个星期`与`过去7天`生成同一个连续7天窗口，截止本次解析时间；旧的“只生成起点”改为明确起止时间，不把未来时间事件混入。
- 支持阿拉伯数字、常用中文数量（一至九十九、一百）、a/an，以及天、周/星期、月的中英文单位。连续天/周上限3650天，月上限120个月。
- `过去一个月`按日历月回退，例如3月31日回到2月28日（闰年29日），保持UTC时分秒。不是固定30天；`上个月`与`上周`是另一种日历区间，当前不自动推断。
- 旧版/compliance的今天、昨天按UTC日界解释，返回过滤条件均为带UTC时区的ISO时间。产品用户时区尚未接入，不能把“昨天”称为新加坡本地日界。
- 未支持的时间形式（如上周、过去一季度、明确日期区间）或同时提出多个时间范围，返回明确400错误；不静默当作无时间条件。可在API中明确提供带时区的start/end，服务采用该结构化范围。未提出时间条件时仍允许有界查询全部时间。
- 本次没有给日志增加时间字段、没有调用LLM解析条件，也没有更换模型。

## 模型分工的下一版方向

普通回答、名称检索和工具选择可继续采用Flash；Radar调用成功后，用另行配置的推理模型综合工具证据，同时收紧关联/因果/状态/未知时间表达。当前Radar仍复用回答模型，独立升级路由尚未实现。

审计解释已有 `LLM_AUDIT_MODEL` 与 `LLM_AUDIT_REASONING_EFFORT` 独立配置入口，默认沿用普通回答模型。升级模型不改变日志过滤、脱敏和权限规则；精确计数应由完整过滤结果确定，不能从20条模型输入推断全时段总量。
