# 合规审计查询流程与时间条件

关联 REQ-008。当前实现以规则解析审计问题，模型只解释已过滤、已脱敏的事件，不能访问整份日志、执行 SQL 或决定权限。

1. `/api/audit/ask` 检查当前 admin/compliance 角色及会话；普通员工拒绝。
2. `AuditQueryParser` 提取用户、请求、资料和时间条件。前端显式提交的过滤条件覆盖文本解析；用户简称和问题中资料ID的完整发现仍需后续收尾，本次只修时间。
3. AuditStore 在只读事务中验证哈希链，按过滤条件查询。服务最多选择100条并检查截断；无匹配不证明从未发生访问。
4. 根据查询人的当前业务读取权、证据版本/哈希检查历史问题、回答和证据。合规角色不会自动获得全部业务权限；不可见字段脱敏。
5. 仅“让模型解释审计”调用模型，最多20条事件和40,000字符。模型接收原问题、明确查询范围与可见事件，使用 `[E序号]` 引用。普通条件查询不调用模型。
6. 校验输出格式、事件引用、当前角色与业务权限、审计链；失败回退事件列表。模型前后、记录之后及HTTP交付前均有检查。
7. 审计查询自身追加到审计链，记录调用模型、Prompt、过滤结果数量和已交付答案。

## 2026-10-13 时间解析修复

- `过去一周`、`最近一个星期`与`过去7天`生成同一个连续7天窗口，截止本次解析时间；旧的“只生成起点”改为明确起止时间，不把未来时间事件混入。
- 支持阿拉伯数字、常用中文数量（一至九十九、一百）、a/an，以及天、周/星期、月的中英文单位。连续天/周上限3650天，月上限120个月。
- `过去一个月`按日历月回退，例如3月31日回到2月28日（闰年29日），保持UTC时分秒。不是固定30天；`上个月`与`上周`是另一种日历区间，当前不自动推断。
- 今天、昨天按UTC日界解释，返回过滤条件均为带UTC时区的ISO时间。产品用户时区尚未接入，不能把“昨天”称为新加坡本地日界。
- 未支持的时间形式（如上周、过去一季度、明确日期区间）或同时提出多个时间范围，返回明确400错误；不静默当作无时间条件。可在API中明确提供带时区的start/end，服务采用该结构化范围。未提出时间条件时仍允许有界查询全部时间。
- 本次没有给日志增加时间字段、没有调用LLM解析条件，也没有更换模型。

## 模型分工的下一版方向

普通回答、名称检索和工具选择可继续采用Flash；Radar调用成功后，用另行配置的推理模型综合工具证据，同时收紧关联/因果/状态/未知时间表达。当前Radar仍复用回答模型，独立升级路由尚未实现。

审计解释已有 `LLM_AUDIT_MODEL` 与 `LLM_AUDIT_REASONING_EFFORT` 独立配置入口，默认沿用普通回答模型。升级模型不改变日志过滤、脱敏和权限规则；精确计数应由完整过滤结果确定，不能从20条模型输入推断全时段总量。
