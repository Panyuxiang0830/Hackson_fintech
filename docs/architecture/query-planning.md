# 问题理解与检索计划（待实现）

日期：2026-10-07。关联 REQ-015、REQ-019、REQ-018。仅记录设计，Query Planner 尚未接入；回答 Prompt v3 不是检索前模型调用。

## 建议流程

服务端解析当前身份 → 保留原问题 → 规则处理／按需模型规划 → 校验计划 → 原问题与少量扩展检索 → 各分支执行相同授权过滤 → 去重融合 Top-K → 用原问题和授权证据生成回答。

- 简单问题先用分词、实体与时间规则；复杂、多子问题或歧义问题再考虑模型，不默认每次增加一次请求。
- 规划模型只接收原问题及必要的已授权范围提示，不能预读全库标题或权限库。模型给出的是检索候选，不是业务事实、权限决定或用户已经确认的“话外意思”。
- 首版建议最多 3 条语义改写、8 个关键词、2 个解释候选，校验长度、枚举、数组与总预算；保留原问题检索。不能把模型输出直接当 SQL、Qdrant filter、user_id 或 principal，来源／项目提示只能与授权范围取交集。
- 口语整理不得删除否定、时间、实体或比较条件。实体纠错需核对当前授权资料的名称候选，多义或改变问题含义时要求用户确认；不能静默把 TibanDB 改为 TitanDB 或 TiDB。
- 规划超时、格式不符或预算耗尽，回退原问题检索而非放开过滤。规划前解析身份，每个检索分支和交付前继续复核当前权限。

## 受限 JSON 示例

仅表示已明确实体问题的检索计划，不是业务答案，也不是已实现接口。

```json
{
  "original_query": "TitanDB 是做什么的",
  "intent": "definition_and_purpose",
  "keywords": ["TitanDB"],
  "semantic_queries": [
    "What is TitanDB and what is its purpose?",
    "TitanDB responsibilities and application use cases"
  ],
  "entity_candidates": [],
  "possible_interpretations": [],
  "needs_clarification": false
}
```

只请求有限候选和澄清信号，不要求或保存完整思维过程。模型回传的 original_query 必须与服务端保存的输入一致，不能覆盖原问题。

## 启用与验收

- 固定样例覆盖中英口语、多子问题、纠错、否定、时间、不同权限用户、规划失败与规划期间撤权。
- 对比不开启／按需开启规划的证据召回、无关扩展比例、回答依据、额外延迟及 Token。生成更多关键词不代表更好，先验证收益再决定启用范围。
- 审计保留原问题、策略／模型／Prompt 版本、受限计划元数据及检索分支数量，遵守现有内容脱敏；不重新加入数据摄取审计模块。完整日志策略仍沿用已确认专题。
