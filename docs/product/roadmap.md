## 集成版之后的建议顺序（2026-10-07）

以下是待实现的后续安排，不属于当前 PR 的功能实现。用户强调的“询问先过大模型拆解，再查索引”明确属于第一项，而不是取得检索结果后才总结。

1. REQ-018/015/019：先建立固定问题与正确证据的评测集，再实现检索前 Query Planner；生成受限 JSON 的子问题、关键词与语义检索句，分别查询关键词和向量索引，融合／重排后使用原问题生成回答。保留原问题检索、权限过滤与规划失败降级，对比不开启与按需开启的质量、延迟和费用。
2. REQ-014：来源感知的信息筛选与分层，优先处理 Slack 线程聚合和低价值内容。
3. REQ-003/004/014/015：增量同步、更新和删除、新鲜度、历史版本与安全回滚。
4. REQ-001/009/011/018：主张与引用的实际支持关系，以及跨来源的时序／权威冲突。
5. REQ-020/018 与已有审计需求：范围确认后再做 Tool、可信最终用户身份和规模测试；小规模质量及成本评测从第一项开始，不等到最后。

阶段背景与当前边界见 [Part A 集成版审查说明](part-a-integration-review.md)，详细问题拆解设计见 [Query Planner](../architecture/query-planning.md)。不恢复已延期的浏览器登录。

2. REQ-015：建立统一分类字段、结构化与向量混合索引，以及结合提问者身份的 Query 路由；
   - 2026-10-07 扩充按需问题拆解、受限 JSON 的关键词／语义改写与纠错确认；[Query Planner](../architecture/query-planning.md) 仍待实现与收益评测，不把回答 Prompt 的修改当成规划模块已接入。

4. REQ-004：保留版本历史，通过 active version 管理过期、撤回和回滚。
