# ContextLedger 产品路线图

> 本文只描述团队的实现顺序，不代表官方提交格式。官方要求以 `docs/source/` 和 `project/requirements.json` 为准。

## 当前基线：MVP v0

已经完成：

- Streamlit 单页原型；
- 四种合成员工身份；
- 检索前权限过滤；
- 关键词跨来源检索；
- 带引用的 Mock/LLM-compatible 回答；
- 完整审计字段、哈希链和 head checkpoint；
- 合规人员的自然语言/结构化审计查询；
- 运行时权限撤销和身份重解析；
- 来源更新时间、同步时间和过期证据过滤；
- 权限泄漏、篡改、权限变化、新鲜度和端到端测试。

## P0：Handbook 安全闭环（已实现，待人工演示验收）

1. REQ-006：记录完整审计字段和逐文档授权决定；
2. REQ-007：审计事件哈希链、sequence 和独立 head checkpoint；
3. REQ-008：合规人员自然语言/结构化查询，查询行为本身也被审计；
4. REQ-005：权限撤销后下一次请求立即使用新权限；
5. REQ-004：来源更新时间、同步时间、同步目标窗口和过期状态。

自动测试已经覆盖 P0。合并前还需在 Streamlit 中人工走完权限撤销、新鲜度变化、审计查询和完整性展示。

## P1：补齐跨平台和 LLM 能力

1. REQ-003：为四种来源分别建模 ACL，不使用统一布尔权限代替；
2. REQ-001：增强跨来源关联、排序和引用；
3. REQ-009：接入真实模型 API，校验引用并增加无证据拒答评测；
4. 建立 20–30 个包含正例、拒绝、权限变化和新鲜度的评测问题。

## P2：形成差异化能力

实现 REQ-011 时序与权威冲突检测：

- 区分事件时间、采集时间和生效时间；
- 为来源配置权威等级；
- 区分真实业务冲突、旧消息和未收到通知造成的 awareness gap；
- 仅在证明因果关系有价值时引入 Lamport/Vector Clock。

## P3：整理最终交付

先完成产品，再根据 REQ-013 中确认后的提交字段准备：

- Demo walkthrough；
- 系统架构和 trust-boundary diagram；
- 评测结果；
- 视频、部署、Pitch Deck 或正式报告（仅在要求确认后确定格式）。
