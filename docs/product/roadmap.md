# ContextLedger 产品路线图

> 本文描述团队实现顺序，不代表官方提交格式。需求状态以 `project/requirements.json` 为准，官方场景以 `docs/source/` 为准。

## 最新优先级：一周内先完成五场景（2026-10-10）

用户确认距离提交约一周、三位同事参与。完整任务、工作量、依赖、分工、七天安排与验收门槛见 [后续 Workload](workload.md)。本次只更新计划，不将待办改成已完成。

2026-10-11 用户确认开始实施：四项已在工作分支接入，零证据控制流通过合成回归；复核已选当前 GLM，通过单独调用完成而非独立模型验证。模型审计/复核/规划仍需真实 API 与效果验收，尚未部署。去重归入既有团队扩展，不变成官方指定实现方式。详见 [模型链路实施说明](../architecture/llm-workflows.md)。五场景、新鲜度与来源撤权的优先级不变，不重启一周计时。

1. 建立五场景评测真值和脚本，跑当前集成服务基线。
2. 并行补数据新鲜度链路、来源撤权验证、合规模型问答及零证据 Demo；回归已有跨来源问答、引用和无权限负面案例，验收首版规划与单独调用复核。
3. 五场景端到端验收、真实回答质量与时效报告、人工走查和提交材料。
4. P0 与近期补充通过后，再考虑规划策略优化、来源感知筛选/分层、分类路由/重排和回答预算优化。
5. 完整版本回滚、跨来源冲突、更全面的自动主张核对/修正、规模/生产审计与未来 Tool 放在后续。

本顺序覆盖 2026-10-07 的“先评测再 Query Planner”安排：**评测仍先做，但五个 Handbook 场景的缺口高于新增 Query Planner。** 演示与提交材料从第 1 天准备，不再等所有增强完成才开始。

## 已合入的集成基础与尚未证明的能力

2026-10-08 的评测、集成及性能改动已通过真实 gpushare 重建与走查，后经 PR #5/#6 合入 main。记录中的部署规模为 45,565 篇原文、591,294 条新 MiniLM 向量；17860 保留 Part A 风格前端，旧 collection/快照、原 7860、身份权限与审计保留。该记录不是本次重新检查服务器在线状态。

现有基础包括：

- 持久化身份权限库、独立演示管理员和六名员工；OIDC 默认停用，演示身份不是生产认证。
- Qdrant 与关键词查询前置权限过滤、服务端证据复核及索引快照一致性检查。
- 授权证据组装、真实 GLM 回答、数字引用/授权范围校验与安全降级。
- 持久化系统内撤权、查询/回答/权限变更审计、哈希链和角色受控/脱敏审计查询。
- Part A 固定参考证据检索评测和合成安全回归；BGE/Qwen 等离线实验不自动成为前端排名策略。

仍不能据此声称：真实来源已持续同步、原平台权限变更已自动同步、完整历史回滚已可用、每句答案均有语义证明，或五场景端到端质量/规模评测已完成。源码中的来源权限适配接口明确为 `not_enabled`，当前新鲜度保护只核对已知离线快照。

实施边界与配置见 [统一集成](../architecture/unified-integration.md)，现有人工步骤见 [演示验收](demo-acceptance.md)。初始六员工均为 member；合规角色后端已经存在，但仍须设置受控验收身份、核对审计覆盖和 worked example。不能为了看到全部审计明文而绕过业务资料脱敏。
