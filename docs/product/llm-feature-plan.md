## 审计回答

当前身份/合规角色 → 确定性合法条件查询 → 哈希链检查和当前业务权限脱敏 → 最多 20 个可见事件 → 模型解释 → E 引用编号、角色、证据、链的代码校验 → 页面与追加审计。

原审计问题、选择范围与事件内容分区作为数据。模型不能执行 SQL、扩大时间或用户范围、决定角色、复原脱敏内容；历史问题与回答不是系统指令。部分结果不能当整个时间段统计，无匹配不证明访问从未发生。失败回退确定性查询结果，不展示非法引用的输出。没有模型二次审查或反馈重答。

## 检索前规划

保留原问题 → 启用时一次受限 JSON 规划 → 子问题/语义句进 Qdrant，关键词进 FTS → 所有分支使用同一权限/版本条件 → 文档 RRF 去重，总 Top-5 → 对原问题生成回答。

规划可关闭作基线，超时/格式错误回退原问题；改变实体、时间、否定或意图需确认，不静默纠错。最多 5 个检索分支，不递归调用模型，不接受模型生成的 SQL 或权限表达式。Top-K 是返回数量，不是另一种索引。业务最多 3 次模型请求：规划 1＋生成最多 2（保留既有一次格式重试）；审计最多 1 次，不计为质量保证。

## 零证据与撤权 Demo

无可用证据由服务端返回：

> 本次未检索到足够的可用依据，暂时无法回答这个问题。你可以补充具体信息，或换一种问法。

不猜测资料是否存在，不披露受限资料的标题、链接、ID、数量或拒绝原因，不引用、不调用回答模型。未知问题和撤权后无证据使用相同措辞；未登录、停用账号或索引异常不能冒充正常零结果。

演示顺序：员工有权回答并记录请求/原文 → 管理员在账号和来源绑定仍有效时撤销全部读取权限 → 同题零证据和安全提示 → 旧原文不可读，另一员工仍正常 → 合规人员核对前后请求与撤权事件 → 只恢复本次临时规则到原合法状态。不要初始化整库、恢复其他合法撤权或删审计。

## 取消边界与验收

删除的是第二次模型语义判断及反馈重答，不是权限/版本/格式/编号/角色/哈希链检查。合法编号仍不能保证事实逐句被支持，主要事实在固定评测与 Demo 中人工核对。旧 LLM_REVIEW_* 配置没有作用，专用评测资产已移除，可从 Git 历史恢复，不删除旧日志。

五个 Handbook 场景继续最高优先级。真实模型报告质量、规划收益、五场景真人验收和录制仍待完成；四平台实时同步、新鲜度/有效版本及插件不是因为本轮增加模型功能就已经完成。
