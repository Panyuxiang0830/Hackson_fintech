## 1. 审计回答：只让模型读它能读的结果

处理顺序：当前身份与 admin/compliance 角色检查 → 服务端合法条件查询 → 哈希链完整性检查与业务内容脱敏 → 有界可见事件 → 模型回答 → 事件引用/权限复核 → 页面交付与审计。

用户可以问：“Jax 今天查询了哪些信息，哪些请求在撤权后没有返回内容？”服务端继续控制用户、时间、请求和文档过滤条件；模型不得直接执行 SQL、遍历日志库或指定自己是合规人员。首版复用现有条件解析，必要的模型过滤扩展必须使用受限字段，不另建无权限约束的查询入口。

模型输入包含原审计问题、查询范围、是否截断和本次可见事件。日志里的历史问题/回答是数据，不是新指令。无对应业务资料权限的合规人员可读取被允许的事件元数据，但不能通过摘要恢复脱敏内容。

答案就近标记 `[E序号]`，只能引用本次提供的事件。结果截断时不能把局部事件当成整个时间段的统计；无匹配不能断言从未发生访问；哈希链异常不能当成可信记录继续总结。模型失败时显示现有确定性查询结果，明确没有生成可靠的模型审计回答。

## 2. 回答确认：单独调用复核，不是独立事实保证

业务问答的目标链路：当前身份 → 规划模型 → 授权检索/融合 → 证据权限与版本检查 → 生成模型 → 确定性格式/编号校验 → 单独调用模型复核 → 权限/版本交付检查 → 最终回答。

审计模型答案使用同样的复核原则，但证据是可见审计事件、引用是 `[E序号]`，不能与业务资料 `[1]` 编号混用。

- 用户最新确认复用现有 GLM：默认沿用 `LLM_MODEL` 和现有地址/Key；复核使用单独调用和专用 Prompt。允许另配型号，各阶段参数/实际型号/结果分别记录，不能把同模型两次调用称为独立模型验证。
- 输入限于原问题、未交付草稿和本次授权证据/可见事件。不为验证去扫描全库，不拿受限内容给复核模型“对答案”。
- 检查重要事实有没有依据、引用是否指向支持该事实的段落、数字/时间/状态是否吻合，有无缺引或过度推断。
- 输出受限结构化结果：主张定位、对应引用、支持/不支持/无法判断，以及可在原证据中定位的支持片段。服务端检查 ID 合法、引文确实存在、主张确实属于草稿；这仍不能确定性证明语义支持。
- 原草稿在复核完成前不可见。用户最新决定：复核未通过时返回逐段理由或技术失败提示，交回原生成模型用相同证据重答一次；第二版不再语义复核，但继续格式、引用编号、权限与版本检查。页面展示首次反馈和“重答未再次复核”，不能标为通过，不无限循环。
- 模型前后及交付前仍检查权限与内容版本；复核中撤权也须丢弃。页面区分支持、不支持、无法判断、未配置/不可用和无需复核，不能都显示绿色通过。

复核也可能错，尤其同模型可能重复生成时的错误。用人工标注的正确引用、错引、同名实体、时间/数字矛盾、无依据事实及恶意来源指令评估漏检和误判；记录增加的延迟与费用。不得宣传为“保证每句话绝对正确”。

## 3. 提问先过 LLM：三类输出，各走各的检索

原问题 → 一次受限 JSON 规划 → 子问题/语义检索句进入 Qdrant，关键词进入 FTS → 每路带相同 ACL 与版本条件取 Top-K → 原问题结果一起去重融合 → 总预算内证据 → 回答与复核。

Top-K 是取回多少条，不是第三种检索数据库。启用功能时，规划发生在首次业务证据检索之前；关闭开关用于基线对比，规划格式错误/超时则回退原问题检索。已知没有业务读取范围时可直接使用零证据终止分支，不为显示拒答浪费模型调用。

沿用 [Query Planner 设计](../architecture/query-planning.md) 的有限子问题/关键词/语义改写与总预算；不按数组数量相乘，不对每个子问题递归调用 LLM。保留原问题，实体纠错和“话外意思”只能作为候选，改变原意需确认。模型计划不能成为 SQL、Qdrant 权限过滤表达式或身份决定。

需要开关对比证据召回与答案质量，同时衡量额外调用、Token 和延迟。各阶段可以都用 GLM。业务最坏最多 5 次调用（规划 1、首次生成 2、复核 1、反馈重答 1），审计最多 3 次；重答不再格式重试/语义复核，现有第一次格式重试也计入总预算。

## 4. 零证据：统一提示，不能猜原因

系统指令规则已写入本分支和新版隔离预览的 `answer-v7-2026-10-11`：

> 若 authorised_evidence 为空，只说明本次未检索到足够的可用依据，不能回答业务事实。不得猜测资料是否存在，不得解释是权限、部门、平台或受限文档造成，不得透露未提供资料的名称、标题、链接、ID 或数量。不得生成引用或借助模型训练记忆补全。返回 insufficient 和空引用。

建议默认回复：

> 本次未检索到足够的可用依据，暂时无法回答这个问题。你可以补充具体信息，或换一种问法。

默认服务端在无证据时直接返回该提示，跳过生成/复核模型，既可控又节省 Token。若上游模型需要读取状态，只传原问题与空证据，并执行同样的输出约束；Prompt 只是辅助，不能代替索引权限过滤或服务端终止分支。

“查询未知内容”和“撤权后无证据”使用同一种不暗示受限资料存在的回答；禁止“我找到了某份文档，但你没权限”“系统里根本没有这份资料”等表述。未验证身份、停用账号、索引不可用或同步异常是不同状态，不能掩盖为正常零条结果。

### 必须录制的撤销全部读取权限 Demo

1. 在隔离安全状态中选择一位有合法业务权限的员工，对固定问题正常搜索/回答，记下请求 ID、可见证据和一个原文链接。
2. 管理员记录演示前权限，在账号和会话仍有效的前提下，撤销该员工对本演示数据范围的**全部业务读取权限**；例如设置覆盖四平台的系统内拒绝规则。不借此修改真实企业或原平台权限。
3. 员工再次问完全相同的问题：正常权限过滤后证据为零，返回上述安全提示、空引用，不展示旧回答/旧标题，也不建议受限名称；当前请求不进行生成/复核模型调用。
4. 打开先前原文链接，仍不能读取；另一位有权员工的正向对照仍能使用系统，证明不是全站故障。
5. 切换具有适当权限的合规身份，查撤权事件和前后请求。撤权后可核对零证据状态；前次业务明文是否可读取决于合规人员当前业务权限，不能为演示关闭脱敏。
6. 仅恢复本次临时改变的权限到原合法状态，不批量初始化账号、不删除审计、不恢复已经被其他操作合法撤销的权限。

演示账号停用后返回 401/403、移除全部身份绑定后无法选择数据集，并不自动满足这个“正常请求下零证据回答”的 Demo。实现与测试需明确覆盖保留可信账号但失去读取权的场景。

## 5. 实施与验收边界

四项首版链路已接，接下来按零证据、模型审计问答、检索规划和单独调用复核做真实验收。五个 Handbook 场景仍是最高优先级，新鲜度和来源权限同步不会因为新增模型链路而视为已完成。

正常样例、权限反例、失败降级和调用期间撤权已有合成回归覆盖。无 API 的控制流测试不能冒充真实模型质量；复核已选当前 GLM，真实效果、成本评测及 Demo 录制待完成，不能仅展示一次通过就宣称复核或规划有效。
