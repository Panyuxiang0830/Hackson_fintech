# 一周交付 Workload：先验收五个 Handbook 场景

计划日期：2026-10-10。用户提供的窗口为一周、三位同事。暂按三位同事负责开发、用户负责需求确认、人工验收与展示安排；若用户也参与开发，可作为额外能力，不提前计入交付容量。

这是团队的工作拆分，不是官方新增要求，也不是已完成功能清单。需求状态以 `project/requirements.json` 为准；官方场景依据为 [Handbook 基线](../source/handbook-fintech-track.md)。原文为 10-10 计划，不重启一周计时。

2026-10-11 实施更新：W-05/W-09/W-10 的模型链路代码及合成安全回归已接入 `codex/llm-workflows`，真实型号配置、质量/收益评测和部署未完成；W-08 的中英文提示与保持账号有效的全撤权控制流已验证，录制待完成。详见 [实施说明](../architecture/llm-workflows.md)。五场景完整验收、新鲜度与原平台撤权同步仍未完成，优先级不变。

本周优先交付五个可复现的 worked example、对应的端到端评测结果，以及能让评委理解的演示材料。先补缺口和修复失败样例，再考虑新增智能功能。

### W-01 / W-06：评测怎么做

- 使用同一组小型、可解释的业务资料，覆盖 Confluence 正式方案、Jira 状态、Slack 讨论和 Drive 附件；只有确实相关的证据才进入答案，不强迫每道题同时引用四个平台。
- 每例固定原问题、身份、当前权限、期望证据 ID/版本、答案要点、期望拒答或脱敏行为。包括跨来源问题、证据不足、中英文表达、不可信来源指令，以及标题/链接等元数据泄漏反例。
- 静态问题与动态事件脚本分开：先查 V1，再更新为 V2；先有权，再撤权；先查询，再以合规身份查对应请求。不能只评静态 Recall@K。
- 调用当前集成服务的 API 和实际服务逻辑；测试替身可用于故障/竞态注入，但真实模型质量与部署走查另跑。测试身份、受限标记和正确答案不混入待检索业务正文。
- 开发问题用于调参，留出未用于调参的验收问题；真值不能根据当前检索结果倒推，漏召回不从分母删掉。沿用已有 Part A 评测的分母与覆盖率约定。
- 报告授权证据 Recall@K、人工核对的答案要点/引用支持、拒答表现、用例内泄漏、撤权和更新可见延迟，以及查询耗时、Token/费用。p50/p95 必须标注样本数、重复次数、数据规模与冷热状态；小样本不是百万级性能证明。
- 记录 Git commit、数据/索引快照、模型与 Embedding 修订、Prompt 版本和配置。LLM 可以辅助评判，但关键安全结论与主要引用必须由确定性断言/人工复核确认。

### W-03：新鲜度本周只做必要闭环

先明确 `source_id`、来源版本/内容哈希、来源修改时间、观察/同步时间、索引版本与当前生效版本。新鲜度不是“文件看起来很新”：不知道来源最新状态时要显示 unknown/未检查，不能只刷新时间戳就变成新鲜。

本周交付步骤：

1. 受控来源或已具备访问条件的真实来源产生 V2 更新，连接器/更新入口实际采集该变化；不是手工只改 Qdrant 或测试时间字段。
2. 写入并保留原始与标准化版本，开始更新后标记受影响内容尚未发布；所有检索模式采用同一规则，未就绪版本不能进入模型。
3. 更新关键词与向量索引，核对内容哈希、版本和 ACL；通过后切换当前发布版本。小规模场景允许安全的整快照发布，不为了“一周做完”假装已经有高可用逐文档双写。
4. 再问同一问题，引用 V2 并返回更新后的内容；展示实际来源修改、采集、索引发布、查询时间。
5. 覆盖失败重试/重复事件/旧任务晚到、部分索引失败及删除后不得返回旧内容。失败时明确未同步/拒绝使用，不能继续把 V1 当成当前最新答案。

建议团队本周小场景的更新目标为 **5 分钟内**，第 1 天根据运行方式确认后锁定，并报告真实测量。该数字是团队建议，不是 Handbook 的精确阈值；Handbook 描述的是有界、可预测的数分钟至约一小时。若采用整快照重建，要报告重建期间的可用性代价。完整自动回滚、时间旅行与高可用增量发布留在 P2，REQ-004 不因此整体标为已完成。

### W-04：撤权分两种验收

- **系统内撤权**：管理员撤销平台/项目/文档权限或停用账号，下一次请求立即按新权限执行；覆盖原文、模型调用期间、交付、重启和历史回答/缓存旁路。已交付给用户的内容不能追回。
- **来源权限撤销**：先在来源端移除 Slack 成员或限制 Confluence 页面，由来源权限适配器发现变化、映射到稳定身份与文档/分块，再使后续访问失效。报告“来源变更→观察到变化”和“观察到变化→系统拒绝”的两段延迟；不能把尚未观察到的变更称为即时获知。
- 来源 ACL 与系统内拒绝条件共同生效；同步来源不能覆盖本地拒绝，恢复权限不能超出当前来源授权。ACL 过期、检查失败和同步中状态必须有明确安全策略。
- 先用受控来源适配器验证链路，再验证有访问条件的真实来源。启用真实同步、填写凭据及具体同步窗口须确认，不自动修改当前服务器。现有 `not_enabled` 接口不计为来源撤权场景通过。

### W-05：合规人员验收，不重写审计系统

在独立验收安全目录中由管理员将一个已有演示员工赋予 compliance 角色，或另经确认增加专用合规身份；不重置当前服务器账号/撤权，不让普通用户自行提权。管理角色与合规角色均不自动拥有全部业务资料权限。

完成一次搜索和真实模型回答后，按请求 ID、用户、时间范围和证据 ID 查询；核对身份、时间、问题、最终答案、证据版本、策略/权限版本与实际授权决定。把仍缺的字段或拒绝决定覆盖列为缺口，而不是仅看到哈希链有效就算完整审计。

普通员工直接调用审计接口必须被拒绝；合规人员无权看的业务正文继续脱敏，具有相应业务权限时才能复原对应答案。验证查询审计本身也进入链；在日志副本上做修改/删除检测，不破坏演示日志。不新增已取消的四个数据摄取审计模块，也不把候选审计说成全库逐文档判断。

2026-10-11 新增模型摘要：仅把上述已验证、已脱敏且预算内的结果交给模型，以事件引用回答原审计问题；引用集合、当前角色与业务证据权限在交付前复核。模型失败回退既有确定性事件结果；本扩展还未实现。W-09 接入后审计模型答案也使用独立复核，但不能与业务证据编号混用。

### P0 出门槛

五个 worked example 都有预期、实际、复现步骤和验证范围；固定安全用例无观察到的越权/元数据泄漏，主要事实及引用经人工核对，更新与撤权延迟按锁定目标测量，合规角色能查且普通角色不能查。这个门槛只证明所覆盖用例，不是对所有问题的绝对安全保证。

不能用 Mock 降级冒充真实模型成功；不能用受控来源冒充真实 API；失败场景保留为失败/未验证。如果本周仍缺真实来源访问或同步实现，必须在交付前明确是否满足比赛验收，不因截止临近把需求改成 validated。

第 1 天锁定接口：A 提供来源版本/同步状态/发布结果；B 提供稳定身份、ACL 修订与权限失效条件；C 使用同一接口断言。不要三个人各做一套权限、日期和评测数据。

第 2 天结束检查新鲜度方案、真实来源访问与新增模型任务容量；若超出本周容量，先削减其他 P1/P2，不削减安全检查，不悄悄将 Handbook 场景降级成“以后做”。本次确认的模型扩展不应被自动撤出，但也不能无评估挤占五场景修复；容量冲突须明确报告并确认取舍。每项在短分支通过 PR 交叉审查，冻结版本要经过真实索引/服务器验证，不能只看本机测试。

## 4. P1：五场景通过后再做的增强

顺序延续用户此前构思；本周只有 P0 已通过且有余量时才选择一个小项，不承诺全部完成。

1. **Query Planner 后续优化（REQ-015/018/019，EC-006）**：首版已于 2026-10-11 纳入近期 W-10，但仍未实现；本处只排后续策略优化。用评测收益决定按任务开关、路由和预算，不因为增加模型调用就宣称检索更好。
2. **信息筛选与分层（REQ-014，EC-005）**：四平台分别处理；优先 Slack 线程聚合、低价值过滤、可解释的 Primary/Secondary/Raw Only。保留 Raw 与过滤理由，不混用不同 ACL；模型提取的候选决策不自动当成已确认事实。评估重要事实是否被误删和 Token 节省。
3. **项目/部门分类与路由、融合和重排（REQ-015/001，EC-002/006）**：缩小合理检索范围，同时保留授权范围内的扩展回退，避免过窄路由漏掉跨项目证据。离线 BGE/Qwen 实验必须通过服务端权限和端到端收益验证才接入前端。
4. **回答表达与预算优化（REQ-019/009/018，EC-008/010）**：按任务控制证据数量与模型预算，改善自然分段和就近引用；基于同一数据比较，不能只凭 Prompt 看起来更完整就宣称质量提升。

## 5. P2：后续完整工程能力

- **完整增量同步、历史/回滚和故障恢复**（REQ-004/014/015，EC-001/004）：四平台真实 Connector 覆盖、游标、删除/撤回、幂等重试、可用性更好的索引发布与时间旅行。回滚业务内容不能恢复旧权限。
- **身份与来源 ACL 全面对齐**（REQ-003/016，EC-002）：多组、多项目、多部门与离线权限推断统一；不恢复已延期的 Auth0 登录页面。
- **更全面的逐主张核对与跨来源冲突**（REQ-001/009/011，EC-007/008）：人工依据验收仍在 P0，首版独立模型复核已纳入近期 W-09，但仍未实现；此处是更全面的主张切分、核对/修正策略、权威/时间判断与冲突解释，不用逻辑时钟单独判定事实正确性。
