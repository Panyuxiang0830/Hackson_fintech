# ContextLedger 未来工具入口范围（延期）

日期：2026-10-06。关联 REQ-016、REQ-017、REQ-020；决策见 [ADR-0003](../decisions/ADR-0003-tool-first-and-deferred-browser-login.md)。

## 范围澄清

用户已明确：Tool 是后面的设想，现在不用做。本轮仍在 Part A 前端验收 REQ-017，真实浏览器登录延期，身份权限库、管理员、检索与审计不取消。REQ-020 为 deferred，下述设计不作为当前交付前置条件。

## 未来设想

用户在上游 Agent 中提问，Agent 运行时在模型之外验证并携带最终用户身份，调用 ContextLedger；ContextLedger 按当前权限检索并返回授权证据，供上游模型回答。身份不放在允许模型任意选择的工具参数中。

这里的“上游”是可信应用运行时，不是大模型本身。简单传入 `user_id="Alice"` 或使用一个共享 API Key 不能证明是谁在查询。最终采用什么凭据、如何绑定用户，以及通过什么协议调用，仍需确认。

## 已有与未有

| 部分 | 状态 |
|---|---|
| Part A 原始 / 标准化存储、来源解析及 Embedding 基础 | 已有，保持复用 |
| 身份权限库、来源身份绑定、本地限制与权限版本 | 已有 |
| Qdrant / FTS 授权前置过滤、候选二次检查 | 已有 |
| 统一检索、原文读取、回答、交付检查和查询审计 | 已有，外部入口仍需可信身份 |
| 浏览器 OIDC / Auth0 登录 | 已有可选代码，本轮延期，默认关闭 |
| Part A 风格页面 | 当前集成和人工验收入口；已确认并实现显式隔离的七账号演示模式 |
| MCP / HTTP Tool / 本地工具适配层 | REQ-020 deferred，尚未实现或选定协议 |
| 最终用户身份从上游传递并验证 | 待设计，不能用模型参数代替 |

浏览器登录关闭后，普通生产业务接口仍拒绝未验证身份。当前采用显式启用、回环／SSH 预览中的隔离演示模式验收前端，不先实现 Tool 或继续配置 Auth0；演示选择账号不能当作生产鉴权。

## 后续 Tool 专题（当前不执行）

1. 确定上游 Agent 所在应用及工具协议。
2. 定义由运行时注入、服务端验证的最终用户身份上下文，与身份权限库稳定用户 ID 映射。
3. 工具默认返回少量授权证据及来源、版本、请求 ID；复用 `UnifiedService.search` / `open`，不重复维护检索与 ACL 逻辑。
4. 优先做两个权限身份的同问题隔离、伪造身份拒绝和撤权用例；不依赖浏览器登录演示。
5. 决定回答位于上游还是继续调用内部 `ask`，避免一次检索不必要地重复调用两个回答模型。

原平台 ACL 实时同步、新鲜度和版本回滚、筛选与规模评测等延期事项不因入口变化而自动完成。工程难题仍以固定 EC-001 至 EC-010 清单为准。
