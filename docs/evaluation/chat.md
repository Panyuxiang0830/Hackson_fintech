## 运行方式

从仓库根目录按照 [英文 quickstart](../../BENCHMARK_QUICKSTART.md#real-model-answers-and-browser) 启动原生 Qdrant 1.19.1，配置本地 `.env`，运行：

```bash
.venv/bin/python scripts/evaluate_chat.py \
  --qdrant-url http://127.0.0.1:16338 --out runtime/chat/run --serve
python3 scripts/check_chat_ui.py --out runtime/chat/ui
```

默认使用本地配置的真实模型；未配置 Key 或使用 Mock 时直接报错。`--model MODEL_ID` 用于对照，`--env-file PATH` 可指定仓库外的私有配置。每次运行使用新目录，避免覆盖结果、权限或审计。浏览器检查需要另外安装 Playwright 和 Chromium；它不是生产服务依赖。

## 固定协议

- 17 份合成文档，来源为 Confluence、Jira、Slack、Google Drive；没有真实企业正文进入 API。
- 42 次观测：24 个可回答问题、9 个未知实体／无权限问题、6 个修改前后问题、3 个撤权后问题。前 24 个问题包含 10 个英文问题。
- 使用真实 MiniLM CPU、原生 Qdrant、实际 `/api/ask`、固定演示会话、CSRF、IdentityStore 和哈希链。检索前规划关闭；自动 Radar 保留，综合阶段仍使用同一模型 high 和独立预算。
- 更新通过实际管理员 HTTP API 和持久化发布任务；关键词、向量、混合模式分别核对 5 万→12 万，以及引用文档的当前内容哈希。本项在发布 ready 后测答案，不能当作在线新鲜度曲线。
- 两个并发问答 worker，temperature=0，普通输出上限 1600、Radar 上限 6000。API／格式失败和正常拒答保留在分母，不额外成功重跑来替换失败。
- `protocol.json` 保存模型、Prompt、源码和夹具指纹；`results.jsonl` 保存问题、实际回答、证据、逐项检查、诊断与耗时；`summary.json` 按类别统计；`update-job.json` 保存发布结果。密钥不进入这些文件。

## 判断范围

可回答问题核对金额集合、指定事实／状态模式、期望文档是否检索和引用、引用是否合法、证据哈希是否为当前版本，以及中英文问题是否按对应语言回答。拒答检查空证据、空引用、零生成调用；撤权使用相同检查。浏览器检查空输入、回答与证据显示、原文打开、身份切换、迟到响应、手机横向溢出和 JavaScript 异常。

这些是固定回归问题的检查，不是逐句语义正确率。金额和状态正确仍可能伴随未被资料支持的修饰语，引用编号合法也不证明每句话都有依据。选择模型和修订 Prompt 使用了这些问题，因此不报告未见测试集成绩。当前入口为单轮问答；追问需要保留业务名称，不提供会话记忆。来源平台自动轮询、生产身份、完整来源 ACL、规模吞吐与成本不在本次范围。

人工阅读仍发现过度解释，例如 BeaconDesk 回答中的“确保每个请求得到处理”、HarborLedger 英文回答中的“所有收支”，均超出了原始资料的明确支持范围。因此 42/42 只表示表内回归检查通过，不能写成完整语义准确率 100%。

Qwen3.5 Flash 在新增 Radar 链路上出现空答案、把引用编号当业务 ID 和不合法结构化输出。普通定义／单事实表现与复杂工具路径分开统计，不能沿用上轮没有 Radar 的质量结果。

回答 Prompt v10 区分“有依据的回答”与“业务已批准”：待审批、不生效或资料冲突仍应解释已有事实，不能把拟议额度说成当前有效额度。定义回答只使用资料支持的内容，首句也要求引用。Radar v4 将原问题和当前授权证据中的可选原生编号传入路由，名称起查可用空列表；工具继续校验参数、权限和版本。OpenRouter 使用官方统一 `reasoning` 参数并排除推理正文，不接收或展示思考过程，其他兼容端点保留原参数。

英文问题曾出现整段中文答案，新增有界语种检查：明确英文问句、未要求中文翻译或原文引用时，明显以中文为主的输出使用既有一次格式重试，重试前继续复核权限；再次失败安全降级，不增加模型复核或重答循环。输出语言检查覆盖已观察到的中英错配，不是通用语言识别器。

OpenRouter 参数依据：[官方 reasoning 文档](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)。参数适配不能保证某个模型的工具选择、格式或语义正确。

## 2026-10-13 页面与 API 错误交互修复

私有 HTTPS 实测发现：当前问答收到 403 或 409 时，API 包装器先清除证据并递增页面请求代次，调用方随后将同一个请求的错误误判为旧响应，因此回到初始页面而没有显示拒绝／冲突原因。旧请求的错误还可能清空新身份的页面。

修复将请求代次保存在 API 错误中：只允许当前请求清除证据，并允许同一错误触发的清理后显示提示；身份或问题变更后的旧成功和旧错误仍丢弃。问答、原文和审计使用同一约束。浏览器回归新增真实后端 CSRF 拒绝、409/503 与断网失败注入、旧错误延迟交付；注入结果不计入真实模型质量。

本轮固定已部署页面进一步实测 13 次 `/api/ask`（8 个业务问题、1 个省略名称的追问、1 个未知实体、3 个越权模式）与 18 项浏览器交互；结果与页面、引用卡片和当前原文一致，无 JavaScript 异常。TracePay 关键词／向量／混合均为更新后的 120000 元，QuartzPay 的 60000 元仍待批，CedarPay 的 70000 元已生效；MossBudget 40000／55000 的冲突触发真实 Radar，页面显示实际工具事件。英文回复与 Lin／2026-11-02 两个事实均正常。

6 个明确参数／CSRF／Origin／HTTP 方法拒绝检查通过；另一个探测最初假设额外 `user_id` 应返回400，但实际为忽略该字段并继续使用会话身份。原始探测保留该不匹配，随后以 outside 传 alice 的真实 ID 验证仍为零证据／零模型调用，并核对审计主体为 outside；不把忽略字段误记为身份伪造成功。

省略名称的追问虽经重新检索找到日期，却检索了16份授权记录并使用 Radar，用时57.92秒；冲突问题28.08秒，其余8个明确业务问题中的7个为2.35～19.65秒。页面因此明确提示每题独立、追问保留项目名。这些是小规模合成演示的实际 HTTP 观测，不是容量／通用语义准确率结果。报告保存在 `runtime/deploy/tailnet/chat-interaction-20261013/`，区分正常实测、失败注入和初始探测的预期误差。
